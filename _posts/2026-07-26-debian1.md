Para esta fase, eu e minha dupla escolhemos contribuir para o Debian. O processo de contribuição foi guiado pelo [Guia de empacotamento](https://debianbrasil.org.br/pt-br/empacotamento) (passos 0, 1, 2 e 3)

## 1. Etapa Preliminar: Criação do Ambiente Virtualizado e Configuração do Ambiente de Desenvolvimento

Para realizar a contribuição sem impactar o sistema principal da máquina host, o processo iniciou-se com a criação de uma máquina virtual no **VirtualBox** executando o **Debian 13**. 

Com o sistema base pronto, o ambiente foi provisionado para o empacotamento. Isso envolveu a instalação do conjunto essencial de ferramentas (`sbuild`, `mmdebstrap`, `git-buildpackage`, `devscripts`), a padronização das credenciais do desenvolvedor no Git e `.bashrc`, e a criação de uma imagem base limpa (*chroot unstable*) via `sbuild` para compilação isolada dos pacotes. A validação da infraestrutura foi confirmada com um *build* bem-sucedido do pacote de teste `hello`.

## 2. A Contribuição Executada

Com o ambiente pronto, foi iniciada a tarefa de contribuição ("contribuição de uma linha"):

* **Pacote Selecionado:** `fortunes-mario` (obtido no repositório oficial do Salsa).
* **Alteração Técnica:** Remoção do campo redundante `Priority: optional` no manifesto `debian/control`. Essa alteração segue as diretrizes modernas do empacotamento Debian, onde `optional` é assumido como valor padrão pelas ferramentas recentes.
* **Documentação:** Inclusão automática das notas no `debian/changelog` usando a ferramenta `gbp dch --commit`.
* **Fluxo no Git/Salsa:**
1. Criação do *fork* no namespace pessoal no Salsa.
2. Ajuste do repositório local e cadastro da chave SSH no perfil do Salsa.
3. Commit formatado segundo as convenções do projeto (`d/control: drop Priority field, optional is default now`).
4. Envio do ramo `debian/latest` e abertura do *Merge Request* (MR) para o projeto oficial.
5. Abertura da *Issue* no repositório do Debian Brasil para alocação e revisão por pares.

O MR foi aceito de primeira pelo mantenedor Charles poucos dias após a submissão.

## 3. Conclusão

Como visto, foi uma experiência bem simples e fácil. Muito bom o suporte dado pelo time do Debian (principalmente pelo Charles que foi quem orientou a gente), os tutoriais são ótimos e o processo é bem mais simplificado que o do Kernel.
